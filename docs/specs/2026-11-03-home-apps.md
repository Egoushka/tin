# Spec: Tin Home, app handling a daily launcher needs

Date: 2026-11-03. Status: build plan. Yehor, 2026-11-02: Home is "really not usable" as a daily launcher. Slice 1 of
`2026-11-02-home-launcher.md` drew the drawer and the dock; this spec adds what every stock launcher does with an app
once it is on the screen.

## Goal

Long-press any app (drawer tile or dock) and get what Android's own launcher gives: app info, uninstall, the app's
shortcuts, hide, pin. The dock is Yehor's five apps, not five fixed jobs. The drawer is always the list of what is
installed, without a restart. Unread notifications show as a dot on the icon.

Value hypothesis: with these, the stock launcher has no job left that Home does worse, so the 7-day trial of
`2026-11-02-home-launcher.md` can run. **It has failed if the stock launcher comes back for one of these jobs.**

## Facts this rests on (read at `59c3151`, PR Egoushka/tin#24)

- `AppRepository.changes()` already registers a `LauncherApps.Callback` (added, removed, changed, available,
  unavailable) and unregisters it in `awaitClose`; `keepLoaded()` reloads on each event. The gaps are: it cannot be
  unit-tested (it needs a `Context`), the icon cache is never invalidated (an updated app keeps its old icon until
  the process dies), a burst of events queues one reload each, and profile add/remove (work profile on or off) sends
  broadcasts, not package callbacks.
- `LauncherApps.getShortcuts` answers only while Home is the default home app; otherwise it throws
  `SecurityException`, which the sheet treats as "no shortcuts".
- `cmd notification post` posts as `com.android.shell`, which has no launcher icon, so it cannot light a tile. The
  dot check uses a fixture app that posts for itself.
- Packages of notifications are not split by profile in `Note`; a dot lights for the package in every profile.
- DataStore `tin.tune` exists once per process; the dock and the hidden set are two more keys in it (a second
  `preferencesDataStore` on the same file throws).
- CI (`.github/workflows/ci.yml`, #23) runs `:speech:testDebugUnitTest :home:testDebugUnitTest :home:assembleRelease`;
  lint and `:fixture` run locally with the command in A1.

## Scope

1. **Live list.** One `AppSource` interface (load, changes); the system one wraps `LauncherApps` and the managed-profile
   broadcasts. `AppList` turns source events into the model: bursts collapse to one reload, changed packages are
   reported so their icons are redrawn. Everything but the system source is plain Kotlin and unit-tested.
2. **Long-press sheet** on any tile and any dock icon: header with the icon, then the app's shortcuts (enabled,
   labelled, unique, manifest then dynamic by rank then pinned, at most 5, only the tile's activity or app-wide),
   then App info (`LauncherApps.startAppDetailsActivity`), Pin to dock / Replace, Pin to Home / Unpin from Home (#29's `pinToHome`; hidden once 12 are pinned), Hide from drawer (tiles and dock
   icons alike; a hidden app that is docked stays in the dock), Uninstall (`ACTION_DELETE`; the system confirms).
   Glass card, rows radius 16, 48 dp targets, five type sizes, Lucide glyphs (`info`, `trash-2`, `eye-off`, `pin`,
   `arrow-up-right`, added to `Lucide.kt` and `lucide-icons.json`, bodies from lucide-static 0.460.0).
3. **Your dock.** Five slots of app keys, drawn with the same themed monochrome icon as the drawer on the same 56 dp
   glass circle. Nothing stored = today's handlers (dial, messaging, camera, browser, maps) resolved to launcher
   apps by package, so the first start looks the same. The first change stores all five. A default with no handler
   (GrapheneOS ships no maps app) keeps today's glyph and fallback intent until the slot is filled. Replace: the
   dock icon's sheet opens the drawer in pick mode (title "Choose an app", a tap fills the slot); Pin to dock on a
   drawer tile shows a row of five circles to choose the slot. An app already in the dock swaps places with the slot it is moved to.
4. **Hidden apps.** A set of app keys. Hidden apps leave the drawer and search. Tune gets a "Hidden apps" row that
   opens a list with Show.
5. **Notification dots.** `TinListener` already reads active notifications; `Glance` gets the unread count per
   package for all apps (the chips keep the top 3). A tile or dock icon with a count shows a dot in `ink` (calm has
   no colour); its TalkBack label adds "has notifications".
6. English and Ukrainian strings for every new string.

Out: folders, drag to reorder, per-app badges with counts, shortcut icons (rows use one Lucide glyph), pinning
shortcuts to Home, icon packs, work-profile badge on the tile.

## Acceptance checks

`A` = unit test, run from `android/` with `./gradlew :home:testDebugUnitTest`. `D` = device, phone on USB with Home
as the home app, run from `android/`; `F` = `io.github.egoushka.tin.fixture`, a throwaway app (`:fixture`, one launcher
activity and a receiver that posts or cancels one notification) so no check uninstalls something Yehor uses.
