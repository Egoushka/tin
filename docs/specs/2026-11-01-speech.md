# Spec: on-device speech to text (part 5)

Date: 2026-11-01. Status: scope from the phone-layer proposal
(`~/Projects/context/ai-setup/drafts/2026-11-01-phone-layer-proposal.md`, finding 8 and part 5).

## Goal

Voice commands and transcripts in Ukrainian and English, recognised on the phone with no Google services and no
network. An agent calls one MCP tool on tin and gets text back; a push-to-talk button on the phone records a command
whose transcript the agent can read.

Value hypothesis: GrapheneOS users have no good on-device Ukrainian dictation for agents; a small, reusable Kotlin
module (MIT) around sherpa-onnx fills it. Cheapest test: the module and its benchmark table in this public repo; count
issues and forks. Voice typing in every app stays with FUTO Voice Input (proposal part 5): this is not a keyboard.

## Facts this rests on

- FLEURS word error rate from other people's runs: Parakeet-tdt-0.6b-v3 6.8% uk, Whisper large-v3-turbo 7.3% uk,
  Moonshine base-uk 14.4% (models.handy.computer). Our own run replaces these (check S1).
- sherpa-onnx 2.0.1 ships an Android AAR (all ABIs, 49 MB) and a JVM jar with macOS arm64 natives. Parakeet is an
  offline (non-streaming) transducer there, so "streaming" means the standard sherpa pattern: the mic feeds a voice
  activity detector (Silero VAD), and each finished speech segment is decoded.
- tin's MCP server runs as the shell user (uid 2000); SELinux refuses app uids on its socket. The host app already
  holds a Binder to its Shizuku user service.

## Design

- **`android/speech`, a Kotlin Android library** with no dependency on tin, so other apps can take it:
  - `SherpaRecognizer` (named `SpeechEngine` in the first draft): loads Parakeet int8 (encoder, decoder, joiner, tokens) and Silero VAD through sherpa-onnx; turns
    16 kHz mono float samples into text. Behind an interface `Recognizer`, so the logic below is tested on the JVM
    with a fake.
  - `Listener` (first draft: `Segmenter`): feeds mic chunks into the VAD (`SherpaVad`) and decodes finished
    segments; caps a segment at 30 s. A command ends at the first segment; a recording is decoded whole up to 30 s
    and split by the VAD beyond that.
  - `PushToTalk`: state machine idle → recording → decoding → idle; a press while decoding is ignored; a release
    with under 0.3 s of audio is dropped.
  - `Transcripts`: ring buffer of the last 20 results with id, start time, audio seconds, decode milliseconds, text.
  - `ModelStore`: the model files under the app's `files/models/<name>/`, each pinned by size and SHA-256 in a
    manifest; `verify()` reports missing or corrupt files. Download from Hugging Face is the app's choice; the dev path
    is `scripts/speech-push-model.sh` (adb push + `run-as` copy, debug builds only).
  - `Protocol`: one JSON request per line, one JSON response per line (see below), pure Kotlin.
- **Host app**: `SpeechService`, a foreground service of type `microphone`, started from the app's screen (Android
  only lets a microphone service start while the app is visible). It owns the engine, `AudioRecord`, the push-to-talk
  notification action and a Quick Settings tile. It hands its `ISpeech` Binder to `TinService` over the existing
  Shizuku Binder. `TinService` (uid 2000) serves `@tin-speech`, an abstract Unix socket that, like `@tin`, answers
  only uid 0 and 2000, and forwards each line to `ISpeech`.
- **Core, Rust**: `core/src/speech.rs` adds two MCP tools when the policy says `[speech] enabled = true` (default off:
  a mic is as sensitive as a money function is risky):
  - `speech__transcribe {seconds?: 1..60 = 8, file?: string}`: records from the mic until the VAD sees the end of
    speech or `seconds` pass, or decodes `file`, a WAV under the app's `files/bench/` (a bare name, no path). Returns
    text, language left to the model, audio seconds and decode milliseconds.
  - `speech__push_to_talk {since_id?: int}`: the push-to-talk transcripts newer than `since_id`.
  Names follow tin's rule (`[A-Za-z0-9_-]`, which Claude's API also requires), hence `speech__transcribe` and not
  `speech.transcribe`.
- **Wire format** on `@tin-speech`: `{"op":"transcribe","seconds":8}` / `{"op":"transcribe","file":"x.wav"}` /
  `{"op":"transcripts","since_id":3}` → `{"ok":true,"text":"…","audio_s":2.1,"decode_ms":180}` /
  `{"ok":true,"items":[…]}` / `{"ok":false,"error":"…"}`.

## Out of scope

A keyboard (FUTO Voice Input), wake words, speaker diarisation, call recording (proposal "call companion"),
translation, an in-app model download UI beyond a button, Moonshine (only if the stop condition fires).
