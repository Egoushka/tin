# tin audit, 2026-11-14

Audited `origin/main` at `d0c7daa`. Depth: standard, run by hand: five isolated finders (defects in the Rust core,
defects on Android, reliability, structure, outside and usage), the lead verifying core defects in code, and one fresh
verifier for the Android ones. The machine-readable record is [`2026-11-14-tin.audit.json`](2026-11-14-tin.audit.json).

## Bottom line

The core's safety rules hold: no shell, signed decisions compared in constant time, a ticket runs once, and money
refusal cannot be lifted by policy. The real holes sit at the edges. A web page on the computer can call tin's tools
through `adb forward`. A hung phone command blocks tin forever. Banking apps can be opened, and their notifications
read, through system tools. Home can lose every widget, or crash, on one bad read.

## Last audit's yield

None: this is the first audit of tin.

## Fix now

Confirmed, medium or worse, worst first. "PR" is the fix in flight.

1. **A web page can call tin's tools** (high). Over `adb forward tcp:7381`, every connection reaches the phone as the
   shell user, so the uid check passes for any local process, a browser included. `/mcp` reads the body as JSON
   whatever the `Content-Type` (`core/src/transport.rs:215`). A cross-origin `text/plain` POST needs no CORS preflight,
   so it reaches the tools; DNS rebinding can also read the reply. The MCP spec says servers must check `Origin`.
   Fix: 403 on a foreign `Origin` or `Host`, 415 unless `application/json`. S. **PR #53.**
2. **Banking apps through system tools** (medium). `system__launch` opens a banking app after a tap on an item
   titled "open <package>" (`system.rs:140`). `system__notifications` returns banking notifications (amounts,
   balances), while `screen_text` refuses banking screens (`system.rs:174-193`). Fix: refuse the launch before an
   approvals item exists, and leave banking apps out of notifications. S.
3. **An empty approvals key makes decisions forgeable** (medium). The key file is trimmed and used as is
   (`main.rs:96-104`, `gate.rs:143`); an empty file gives a zero-length HMAC key. Fix: the gate refuses to start
   below 32 bytes. S.
4. **A hung phone command blocks tin forever** (medium). `run_argv` and `cmd app_function` have no time limit
   (`backend.rs:37`, `:53`); `uiautomator dump` is known to hang on animated screens. The Mac backend already has
   `run_with_timeout` (`macos.rs:386`). Fix: share it. S. **PR #56.**
5. **Unbounded request lines and no idle timeout** (medium). `read_line` has no cap on either listener, and the unix
   socket never times out a silent client (`transport.rs:105-201`). Fix: 8 KiB lines, 100 headers, 60 s idle. S.
   **PR #53.**
6. **Home can erase every saved widget** (medium). `WidgetHost.liveIds()` returns an empty set when the widget host
   query throws, and `HomeState` then reconciles against it and saves (`WidgetHost.kt:148`, `HomeState.kt:63`).
   Fix: skip the reconcile when the query failed. S.
7. **A NULL in the Needs-you feed crashes Home** (medium). `NeedsYouSource.read` passes `getString(id)` into a
   non-null field and catches only two exception types; the `Signals` scope has no handler (`NeedsYouSource.kt:68`).
   Fix: skip null rows, catch wider. S.

### Minor

- **Concurrent `screen_text` calls share one dump file** (low, confirmed): `/data/local/tmp/tin/ui.xml`
  (`system.rs:41`). Fix: a file per call.
- **Home's mic may never get tin's `VOICE` permission** (needs validation). `scripts/build.sh` builds tin
  debug-signed, Home's release is signed with the release key, and `VOICE` is signature-level. Missing fact: how
  you install tin on the phone. Yehor.
- Not independently verified (over the verify cap), from one finder each:
  - The release job waits only for the Android job, not for the Rust tests (`ci.yml:148`).
  - `accept.py`'s money check passes on any error that contains "approval".
  - `tin__doctor` reports approvals healthy without probing it.
  - A held call is forgotten when tin restarts, so the later tap gets a 404 (`gate.rs:138`).
  - CI's signer check rejects only the debug certificate; it pins no fingerprint.
  - A late-collected approval still runs, because the signed timestamp is never compared to the clock.

## Build

1. **Tool annotations.** Clients learn which tools only read and which wait for a tap (`readOnlyHint`,
   `destructiveHint`), so a client can auto-allow reads. tin already knows both; `tools/list` sends neither. S.
   Use signal: every tool in `tools/list` carries annotations, and Claude Code stops prompting for read tools.
2. **One definition per verb.** Today a verb is a row in `VERBS` plus arms in four `match` blocks. The wildcard arms
   fail silently: a new verb gets an empty schema and a bare approvals title (`system.rs:90-222`). M. Use signal:
   the next verb (device logs, #45) touches one place.
3. **`tin__doctor` probes approvals.** It reports green with an unreachable approvals URL. S. Use signal: doctor
   turns red when approvals is down.
4. **A release waits for every job.** A release only ships when the Rust tests and the emulator job are green. S.
   Use signal: no `v0.1.N` tag on a red commit.
5. **One test harness.** `Inbox`, `signed`, `gated`, `call` and `text` are copied between `core/tests/system.rs` and
   `macos.rs`. S. Use signal: new gate tests are written once.
6. **Typed AppFunction results.** The `response` metadata in the function list is ignored, so results come back as
   a raw blob; it could become `outputSchema`. M. Use signal: AppFunction tools list an `outputSchema`.

## Wild

Bets, each with a spike of a day or less.

1. **MCP 2026-07-28 beside 2025-06-18.** The newer revision drops `initialize` and sessions. Spike: answer
   `server/discover` and see which clients send the new revision.
2. **Approvals as MCP tasks.** Replace the `approval__wait` polling tool with the 2026-07-28 tasks extension. Spike:
   one held call that finishes without `approval__wait`.
3. **`AppFunctionManager` directly.** Platform API 36 has `executeAppFunction`. Unknown: whether the shell user may
   call it. Spike: one call from the shell user on the Pixel, timed against `cmd`.
4. **Emergency stop.** One tap pauses every write; it needs a change in the approvals app too. Spike: a signed
   `pause` decision that makes the gate refuse.

## Skip

- **Redact every successful result**: it would blank the codes and the word "code" in notifications you ask for.
  Your call instead (Needs Yehor).
- **Screenshot tool**: needs its own money-safety design first.
- **Batch calls**: one approval for many writes weakens the gate.
- **Elicitation for approvals**: superseded by the 2026-07-28 multi-round-trip requests.
- **OAuth on `/mcp`**: the socket is local and reached through adb; the Origin check covers the real threat.
- **`Os.umask(077)` in `TinService`**: verified harmless today, because directories are 0700 before any file exists.
